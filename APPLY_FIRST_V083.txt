ReChair OMS v0.8.3 — 렌탈 회수·반납·재고 전환

적용 전 확인
- v0.8.2가 이미 반영된 최신 ReChair 프로젝트에 적용합니다.
- C:\ReChair 폴더 전체나 .git 폴더를 삭제하지 마세요.
- 이번 버전은 환경변수를 새로 추가하지 않습니다.

1. Supabase SQL 먼저 실행
Supabase → SQL Editor → New query에서 아래 파일의 전체 내용을 붙여넣고 Run을 누릅니다.

supabase/v083_rental_retrieval_inventory.sql

정상 결과는 Success. No rows returned 입니다.

2. 패치 파일 덮어쓰기
압축을 푼 폴더 안의 파일과 폴더를 C:\ReChair에 같은 경로로 덮어씁니다.
.git 폴더는 건드리지 않습니다.

3. GitHub Desktop 반영
Summary:

Add rental retrieval and return inventory workflow v0.8.3

Commit to main → Push origin 순서로 진행합니다.

4. Vercel 배포 확인
Vercel 배포 상태가 Ready가 된 뒤 아래 주소에서 확인합니다.

/admin/rental/operations

5. 기본 사용 순서
① 운영중 또는 계약종료 렌탈 계약 선택
② 회수일시·담당기사·회수사유 입력
③ 렌탈 회수 일정 저장
④ 기사 로그인 후 출발 → 도착 → 작업시작
⑤ 반납상태·후속처리·필수사진·고객서명 입력 후 최종 제출
⑥ 관리자 현장 캘린더에서 작업보고 보기 → 승인 또는 반려
⑦ 승인 결과에 따라 렌탈 상품 상태와 공개 여부 자동 반영

상품 상태 자동 전환
- 재렌탈가능 → 렌탈가능 / 고객 화면 공개
- 점검필요 → 점검중 / 비공개
- 정비필요 → 정비중 / 비공개
- 폐기검토 → 폐기검토 / 비공개

중요
- 연결 상품의 재고수량(stock_qty)이 1 이하일 때만 상품 상태를 자동 변경합니다.
- 한 상품 행에 여러 대의 재고를 묶어 둔 경우 전체 상품을 잘못 숨기지 않도록 자동 변경하지 않습니다.
- 여러 대를 각각 추적하려면 다음 단계에서 개별 렌탈 자산(시리얼 단위) 관리로 확장하는 것이 안전합니다.
